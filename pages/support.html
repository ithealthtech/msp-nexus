Search troubleshooting

Nexus Studio or dynamic blocks are missing

The companion plugin is almost certainly not active. packages/msp-nexus-core owns Nexus Studio, the content model, conditional layouts, dynamic blocks, onboarding, diagnostics, integrations, and the license client.

The theme alone is a supported but reduced configuration. Install and activate the plugin — see install order.

Customizations disappeared after an update

Changes made directly to the parent theme are overwritten when the parent updates. That is how WordPress themes work, not a defect.

Move client-specific CSS, template overrides, and functions into packages/msp-nexus-child. See child theme.

Updates are not appearing

Check, in order: is the license active and the site activated; is the licensing service reachable; and has the entitlement cache expired.

Sites keep rendering from installed code when the service is unreachable, and signed entitlement caches provide a bounded grace state — so a site working normally is not evidence that updates are flowing.

A manifest signature or package hash check failed

Do not work around this. Signature verification failing means the manifest was not signed by a key the site trusts, and a package hash mismatch means the payload is not what was published.

If you recently rotated signing keys, confirm the new public key shipped to sites as a trust-set entry before the private key started signing, and that the prior verification key is still retained. See signed updates.

Otherwise treat it as a potential incident and follow the runbook in LICENSING_OPERATIONS.md.

A download grant link stopped working

Expected. Package grants expire after five minutes and are bound to product, version, license, and site. Request a fresh grant rather than reusing a URL.

The licensing service returns 429

The built-in limiter defaults to 60 requests per client-route per minute and returns 429 with a Retry-After header. Honor that header. For production, add distributed limits at the reverse proxy rather than raising the application limit.

Something breaks only on older PHP

The supported floor is PHP 7.4.33. Run npm run qa:php74, which verifies packaged single-site and multisite installs against that floor through WordPress Playground blueprints — no native PHP or Docker required.

A capability I expected is not there

This is a pre-1.0 release. Check REQUIREMENTS_TRACEABILITY.md, which records requirement-level evidence and the intentional safety boundaries — some absences are deliberate rather than unfinished.

Still blocked?

Open a reproducible issue.

Include the MSP Nexus version, WordPress and PHP versions, whether the companion plugin is active, single-site or multisite, and the exact steps. Never include license keys, portal tokens, signing keys, customer content, or full IP addresses. Use a private advisory for a suspected vulnerability — not a public issue.
