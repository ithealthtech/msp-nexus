Installation

Install in the right order.

The theme renders on its own, but the companion plugin owns Nexus Studio, the content model, and the license client. Install both.

Requirements

ComponentRequirement
WordPress6.7 minimum — tested target 7.0.3
PHP7.4.33 minimum
Node.js22 or newer, for development tooling only

Node is not required to run MSP Nexus. It is only needed to build, validate, and package the product from source.

Install order

  1. Back up firstTake and verify a database and files backup before installing a theme that owns full-site editing.
  2. Install the themepackages/msp-nexus — the full-site-editing block theme.
  3. Install the companion pluginpackages/msp-nexus-core — without it you get the theme's blocks but not Nexus Studio, the content model, conditional layouts, dynamic blocks, onboarding, diagnostics, or licensing.
  4. Activate and run onboardingThe plugin's onboarding flow configures the content model and starter catalog.
  5. Add the child themeOnly if you intend to customize — see below.
!

Activating the theme without the companion plugin is a supported but reduced configuration. Blocks that depend on the plugin's dynamic data and conditions will not render their full behavior.

Child theme

packages/msp-nexus-child is a customization-safe starter. Use it for any client-specific CSS, template overrides, or functions so that updating the parent theme does not overwrite your work.

i

Editing the parent theme directly is the single most common way to lose customization at update time. Start with the child theme even if you only expect to change one colour.

Demo content

The demo directory holds original demo data and deterministic import manifests. Deterministic means a given manifest imports the same content every time — useful for building a repeatable client starting point rather than a one-off.

Validation

The official WordPress Playground blueprints under artifacts/ verify packaged single-site and multisite installs on PHP 7.4.33 without requiring native PHP or Docker. The licensing service test suite covers persistence-domain and HTTP contracts.

See DEVELOPMENT.md and TESTING_AND_VALIDATION.md.

Detailed configuration lives in INSTALLATION_AND_CONFIGURATION.md; upgrade paths in UPGRADE_AND_MIGRATION.md.
